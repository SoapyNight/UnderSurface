# UnderSurface · 晶脉文旅调查

一部 2D 像素风的点击式悬疑调查游戏（DEMO）。

玩家扮演刚毕业的年轻人「小邓」，回到老家度假的十天里，发现爷爷奶奶打算把积蓄投给口碑极佳的本地企业「晶脉文旅」。你要在白天走访景区、居民区与废弃矿洞，夜里打开电脑和手机翻查公开信息与网络传言，拼凑出一条完整的证据链，赶在第十天之前拦住这笔投资。

纯前端实现，无框架、无构建步骤，克隆下来用本地 HTTP 服务器打开即可运行。

---

## 运行说明

### 环境要求

- 一个现代浏览器（Chrome / Edge / Firefox 等，建议最新版）。
- 一个本地静态 HTTP 服务器，二选一即可：
  - **Python 3**（`python --version` 可验证，任意 3.x 均可）
  - **Node.js**（`node --version` 可验证，附带 `npx`）

本项目无第三方依赖、无构建步骤，**不需要** `npm install`。

### 关键前提：必须用 HTTP 服务器打开

**不要直接双击 `game/index.html`（即 `file://` 协议）**，否则游戏无法正常运行。

原因：游戏内的「电脑 / 手机浏览器」通过 `<iframe>` 内嵌 `art/web/*.html` 真实网页，且图片、音频等资源使用 `../art/...`、`../Muisc/...` 这类相对路径访问仓库根目录下的文件。在 `file://` 协议下，这些跨目录资源会被浏览器的同源 / 安全策略拦截，导致黑屏、网页空白或没有声音。

### 启动步骤

1. 打开终端，切换到**仓库根目录**（即包含 `game/`、`art/`、`Muisc/` 的这一层）：

   ```powershell
   cd <解压后的目录>/demo_develop
   ```

2. 在该目录启动静态服务器，任选其一：

   ```powershell
   # 方式 A：Python 3
   python -m http.server 8000

   # 方式 B：Node.js
   npx serve .
   ```

   > 端口 8000 若被占用，换成其它端口即可（例如 `python -m http.server 8080`），下文地址同步替换。
   > 使用 `npx serve .` 时，它默认端口通常是 3000，请以终端提示的地址为准。

3. 浏览器访问游戏入口（注意结尾的 `/game/` 路径）：

   ```
   http://localhost:8000/game/
   ```

4. 进入后按页面提示开始：开场 LOGO → 标题页 → 点击「开始游戏」。

5. 结束游玩时，回到终端按 `Ctrl + C` 停止服务器。

### 验证是否跑通

- 页面出现像素风的标题画面、并能听到标题主题曲，即表示资源加载正常。
- 进入公寓后走到电脑 / 手机前交互，能看到内嵌网页正常渲染，即表示 `art/web/*.html` 与相对路径均正确。

### 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 页面黑屏 / 一直加载 | 多半是用 `file://` 直接打开了 html。请改用上面的 HTTP 方式，并确认访问的是 `http://localhost:8000/game/`。 |
| 图片、网页空白，控制台报 404 | 服务器的工作目录不是仓库根目录。请在含 `game/`、`art/`、`Muisc/` 的那一层启动服务器。 |
| 没有声音 | 浏览器自动播放限制。先点击页面任意处（产生一次用户手势）即可恢复；或检查系统音量与标签页是否被静音。 |
| 改动 CSS / JS 后浏览器没变化 | 浏览器缓存了旧文件。递增 `game/index.html` 中的 `?v=` 版本号，或强制刷新（`Ctrl + F5`）。 |
| 端口被占用 | 换一个端口重新启动服务器，并访问对应端口。 |

## 架构说明

游戏采用「数据 / 引擎 / 引导」三层分离的纯脚本结构，无打包器，直接由浏览器顺序加载。

### data.js —— 声明式内容

挂载为 `window.GAME_DATA`（脚本内简写 `D`），集中定义全部可玩内容，改文字、加场景、调线索都只动这一个文件：

| 字段 | 说明 |
| --- | --- |
| `SPEAKERS` | 说话人表（名称、头像、立绘） |
| `PROLOGUE` | 开场序章文本 |
| `SCENES` | 场景表，共 **20 个**可探索场景（公寓、公交站、居民区、景区、矿洞各区、商店、展馆…），每个场景含背景、可行走范围、热点与出口 |
| `CLUES` / `CLUE_REMARKS` | 线索条目（**32 条**，按 `web_` / `field_` / `res_` / `mine_` 前缀分类）与角色对线索的点评 |
| `RESIDENT_STAGES` / `RESIDENT_TALK` | 居民区 NPC 的分阶段对话语料 |
| `ACHIEVEMENTS` | 成就，共 **16 项** |
| `WEB_PAGES` | 网页 → 线索 / 成就映射表（**45 条**）：登记每个 `art/web/*.html` 的假 URL、可收集线索、关联成就与检索关键词 |
| `PHONE` | 手机相册、音乐等应用数据 |
| `ENDINGS` | 结局文本 |

结局分四种：坏结局 `idle`（什么都没有发生）、`nodoubt`（证据不足）、`doubt`（犹豫之后），以及真结局 `truth`。收集到的线索数量与质量决定最终走向。

### engine.js —— 游戏引擎

挂载为 `window.Game`，IIFE 闭包，对外暴露一组接口。职责包括：

1. 舞台等比缩放（固定 **960×720** 坐标系，`STAGE_W / STAGE_H`）
2. 场景切换与黑幕 / 亮幕转场
3. 主角左右移动、行走动画与场景出口
4. 交互热点、NPC、动态物件
5. 对话框与通用面板（菜单 / 笔记 / 成就 / 设置 / 存档）
6. 电脑与手机（内嵌 `art/web/*.html` 真实网页）
7. 线索 / 成就 / 存档读档 / 结局判定

`data.js` 中的热点通过 `g.xxx()` 回调调用引擎接口，接口集中在引擎的「对外接口」一节。

### main.js —— 引导

`DOMContentLoaded` 后调用 `Game.boot()`，进入开场 LOGO → 标题页 → 游戏主循环。

## 玩法要点

- **十日调查**：有「天」与「体力」的限制，合理规划每天去哪些地点、查哪些资料。
- **双端浏览**：在公寓打开电脑或手机，像真实上网一样访问不同站点——搜索引擎、贴吧论坛、企业信用与工商信息、司法文书与执行信息、政府政策、招聘、新闻报纸、外卖点评等。
- **网页即证据**：每访问一个关键页面，可能写入一条线索、解锁一个成就。`WEB_PAGES` 表负责登记这种映射。
- **多结局**：第十天带着不同数量与质量的证据回家，会进入不同结局。

## 音频与版本号约定

- 三条循环 BGM：室内（`#bgm-indoor`）、室外（`#bgm-outdoor`）、标题页（`#bgm-title`）。进入游戏场景时按室内 / 室外自动切轨；开场 LOGO 与标题页播放主题曲，进入游戏即停止，回到标题页恢复。手机「音乐」App 为独立音轨，与场景配乐互斥。
- 受浏览器自动播放策略限制，若在无用户手势时播放被拒绝，引擎会在首次 `pointerdown` / `keydown` 时补播。
- 静态资源的缓存版本号统一写在 `game/index.html` 的 `?v=20261025`（CSS 与三个 JS 各一处，共 4 处）。**修改任何 CSS / JS 后请递增该版本号**，避免浏览器缓存旧文件。

## 开发约定

- 无第三方依赖、无构建产物，直接编辑源文件、刷新浏览器即可生效（注意上面的版本号缓存策略）。
- 新增游戏内网页时：把 `.html` 放进 `art/web/`，引用公共的 `pixel-theme.css`、`hover-hint.js`、`game-bridge.js`，并在 `data.js` 的 `WEB_PAGES` 中登记其 URL 与线索 / 成就映射。
- 新增场景时：在 `data.js` 的 `SCENES` 中追加条目，热点回调统一走 `g.xxx()` 接口。
